# Modding rakes

Read before writing mod code: patches, entities, behaviours, physics. Stepped on already; don't step again.

- A patch targets vanilla as `game:entities/...`, not `survival:`. Entity files are server-side assets, so an entity patch needs `"side": "Server"`.
- The patch loader reads every file in `patches/`, whatever its extension. To switch a patch off, move it out of the folder.
- An entity's variant is `entity.Properties.Variant["material"]`; `entity.Variant` is not set for entities.
- A variant value carries no domain: `loadFromProperties` keeps a world property's codes by path alone, and a bare `"block/wood"` reads only `game:`. Recipe wildcards match within one domain, and their capture has none. So our vessels take their woods from `roughseas:vessel/wood`, which `WoodsModSystem` writes from every mod's wood list (another mod's wood as `domain-species`), with one recipe file per domain; everything a vessel needs from its wood comes through `Wood`.
- The engine keys a world property's variants by the `code` inside the file, not by its path: two property files with the same `code` in one domain silently share the later one's list.
- Item and entity textures can be rewritten on the server in `AssetsFinalize`: clients get them in the assets packet built after that phase. A code that changes is carried over by the engine's remap files, `config/remaps.json` (blocks and items) and `config/remapentities.json` (entities), which apply on a world's next load.
- The sea and weather model runs on the server alone; a client reads the map the server sends it (`SeaMapClient`), so client code reaches the sea through `SeaWeatherSystem.At` and `Source`, never `Model`. A packet can reach a client before its calendar exists.
- Vanilla's weather is driven, not answered: a region's wind is our Beaufort pattern (`config/windpatterns/beaufort.json`) on a lease, rain enters through `OnGetClimate`, and vanilla's event roll runs. A wind pattern's `Strength` is not synced, only its `BaseStrength`: ours carry a zero-amplitude `strengthNoise` so that vanilla's own update sets one from the other on both sides. A region whose pattern someone else set keeps it until that pattern ends; a jump in time that outlasts our lease is vanilla's roll, and we take the region back.
- Vanilla's event roll weighs events by worldgen rainfall and picks by bare weight, so without our transpiler an event whose conditions fail lives for a tick; with Better and Improved Weather's lightning rates that tick can strike.
- `GenMaps.oceanGen` is the world's own ocean layer and is not thread-safe (vanilla's `NoiseOcean` keeps a shared seed): read it through `GeneratedOcean`, whose lock `OceanGenLock` makes vanilla's chunk thread take too. Never build a second layer: Terra Prety's terrain reads its layer's static instance. The map's numbers mean what each worldgen mod makes them mean; only the built world says where the sea is.
- The chunks `ChunkColumnLoaded` hands over read as empty; read blocks through the block accessor once `GetChunkAtBlockPos` finds the chunk. A map chunk loads before its chunks, so a loaded map chunk does not mean a built column. `WorldGenTerrainHeightMap` is worldgen's snapshot: blocks changed since don't show in it.
- Server physics runs on worker threads. `PhysicsUpdateWatcher` fires from them for a drifting entity, so never touch the world from it: queue the event and act in `OnGameTick`. A steered vessel's physics runs on its controller's client, which fires the watcher on each fixed step with `accum` 0 and once more after its loop with what is left of the frame, after `EntityBoat` has rewritten the motion; the server only replays the rider's packets through it. Measure a steered vessel there and send the result over a channel.
- On a multibox entity `CollidedHorizontally` reflects only the last collision box, and stays false against a wall the hull is pressed into. The physics zeroes each axis of `Pos.Motion` a collision blocked: read that. Contact between entities never zeroes an axis (`repulseagents` only adds a push, and lets hulls slide into each other), so a ram is read where the vessel's physics runs, from the moment the two hulls' footprints first touch.
- A server stall is no event: an autosave stops world time, a lag spike lets it run while the rider's packets queue. Anything measured over the server's clock reads them as sudden stops; `/bridge lag` and `/bridge suspend` reproduce both.
- A steered boat's `Pos.Motion` on the server is its intended speed (`EntityBoat` rewrites it from `ForwardSpeed`, which ignores collisions). The real speed comes from the rider's position packets. The server cannot hold a steered boat back either: an anchor or a leash can only follow it.
- Everything that happens at sea runs on one clock, `SeaWeatherSystem.Clock`: the world's calendar, in game hours and in seconds at vanilla's pace (a game hour is 120 of them by default, as `DefaultShaderUniforms` runs the foliage). It stands under `/time stop` and pause, races while players sleep, and leaps with `/time add`. A mechanic reads its time from a `Clock.StartWatch()` watch, whose `Lap()` gives the time since the last lap, never from a tick's `deltaTime`, the calendar or a stopwatch. Something that builds up (rain in a bilge, a leak, a soaking hull) takes the whole lap, leap included; a run of events (waves striking, lightning) takes the events of the lap's `LivedSeconds` alone, the time the world's ticks ran through, leaving out the hours the calendar was moved on (`/time add`, `/time set`). The clock tells the two apart tick by tick. Motion stays on vanilla's tick physics and its `deltaTime`, as vanilla's boats do: rowing, sailing, drag, a current's push, a mooring's hold, a hull's tumbling through rapids, and the hull's answer to the drawn waves. A tick's real time only paces checks, logs and packets.
- Every decision our code makes logs a debug line, and every hit on a hull logs its cause and outcome. A new mechanic logs its decisions as it is written.
- `Shape.Clone()` copies each element's `FacesResolved` array but shares the faces in it: a face changed in place changes the cached shape every entity of that type draws, and the others then miss its texture. Replace the face with a new one. A vessel's per-place damage marks retexture faces this way (`HullDamage`).
- A light hull floats with its origin above the water's block, so the fluid block at `Pos.AsBlockPos` reads air under a floating currach. Ask vanilla's `Swimming` whether a vessel is afloat; read the block a little below the waterline for what it floats in.
- Vanilla's attachable behaviour finds an entity's wearable slot by its selection box's index, and a box past the last slot crashes the hover help. A box that holds nothing, such as a hull box, gets an empty slot (`"forCategoryCodes": []`) at its index.
- `interactMountAnySeat` mounts a player who clicks any box that is not a seat with an empty hand: a sail cleat, a storage slot. To mount from a hull box, name it as the steering seat's `selectionBox`.
- The new world screen runs before any world loads, and reads a mod's world-setting and playstyle texts only from `assets/game/lang/worldconfig-<code>.json`, with keys unprefixed. In the mod's own lang files they show only in a running world. The bench can't drive that screen: a release zip in `$BENCH_DATA/Mods` that loads without `Failed to find language folder` for it in `client-main.log` is the check.
- A vanilla lang key is overridden from our own lang file as `game:<key>`, which replaces the whole value: there is no patch op for lang. Change only the false sentence of vanilla's value, in each locale vanilla translates; the others fall back to English.
- Writing a vanilla watched attribute with a value of another type (`/bridge set ID clothIds x`) crashes every client that receives it.
- The handbook reads an item's "How to Use" from `<domain>:item-handbooktext-<domain>:<code>`. A lang key with a colon in it is taken as already qualified, so ours is written in full, `roughseas:item-handbooktext-roughseas:reedboat`; written short, it never shows. The description under the name is `itemdesc-<code>`, short.
- A seat with `bodyYawLimit: null` lets the seated body turn with the camera, legs through the hull; ours hold it to 0.4, as the sailboat's do. A passenger faces the vessel's heading whatever its seat's attachment point says. A seat's own `animation` overrides the vessel's `mountAnimations.idle`, and `riderOffset` moves the rider in the shape's frame: x along the hull, toward the stern, z across it.
- A pose leaves room ahead of the seat for the legs: in `roughseas-sitlegsforward` they reach 18 units forward at 3.5 above the floor. `bin/scene seats` shows every seat.
- Player animations of ours are added by patch to `game:shapes/entity/humanoid/seraph-faceless.json` and registered in `game:entities/humanoid/player.json`'s `client/animations`; `bin/model pose` previews them on a copy of the seraph. A held item's motion while the button is held comes from `GetHeldTpUseAnimation`; an animation started by hand is stopped by the game's own held-item handling.
- Liquid containers target water: a bowl held over the sea scoops from it. Bailing happens with the bowl aimed into the boat.
- A vessel that carries its own oars or paddle sets no `requiresPaddlingTool`, and its `mountAnimations` name the rower's strokes; the vessel registers animations of the same codes in its `client/animations`, client-side and at the rower's speed, and `OwnOars` plays each on the vessel at the rower's frame. An animation at speed 0 is never eased out or removed once stopped: it stays on the shape. The rower's arms and the vessel's motion are fitted to each other by the builder (`docs/modeling.md`). The passenger who first took a controllable seat rows, so a vessel keeps one controllable seat, the one its stroke is fitted to; the others carry passengers. A sailing vessel's strokes play only with the sail furled (`EntityVessel`).
- Vanilla's ambient sounds come from a scan of the blocks around the player, on a thread of its own, which asks each block `GetSounds` and `GetAmbientSoundStrength` at its position: one block type can sound differently by place (our surf takes over from vanilla's lapping where the waves break). Whatever those read must be safe off the main thread. Open deep water gets no ambient strength from vanilla; a bed heard at sea is a loop of our own (`Soundscape/SeaBed`), and a splash is played for each crest of the drawn sea passing a vessel or the player (`Soundscape/Splashes`). A wildcard sound path picks at random and may repeat; a pool that must not repeat lists its files with `Assets.GetLocations` (`SplashPool`).
- A keyframe that keys one rotation axis of an element keys all three, and the same for offsets: a missing axis crashes the client in `Animation.lerpKeyFrameElement` the moment the animation starts.
- In first person the player's arms are drawn apart from the world: in their own field of view (`fpHandsFoV`), turned with the camera's pitch (a fifth of it on a seat), from the `-fp` variant of an animation when the player has one. A stroke without a `-fp` variant shows the third-person arms there.
- A block behaviour added in code to a block on the server in `AssetsFinalize` reaches clients with the block, by its registered code and the properties it was initialised with; register its class on both sides (`ShipyardModSystem` gives every vessel wood's lying logs theirs this way).
- `GetClimateAt(..., NowValues).Rainfall` is not the rain falling now: it reads a third under a clear sky with `/weather setprecip 0`. Vanilla's fires ask `WeatherSystemBase.GetPrecipitation`, and so does a fire of ours.
